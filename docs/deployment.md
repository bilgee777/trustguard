# Deployment: Vercel (web) + Render (API) + Neon (database)

All three have a free tier. Nothing here needs a credit card.

```
Browser ──► Vercel (static React app)
              │  /api/*  is rewritten (proxied) to
              ▼
            Render (ASP.NET Core API, Docker) ──► Neon (PostgreSQL)
```

## Why the browser must see one origin

The auth cookies are `HttpOnly` and `SameSite=Strict`. If the web app and the API lived on different sites, the
browser would not send them and sign-in would silently fail. Vercel therefore **proxies** `/api/*` to Render, so the
browser only ever talks to the Vercel domain. This is the same job nginx does in Docker Compose, and it keeps
`connect-src 'self'` in the CSP: scripts on the page cannot call any other site.

## 1. Neon (database)

Use a branch for production, separate from your development branch. In **Connect**, copy the connection string and
rewrite it in the Npgsql key/value format that the API expects:

```
Host=<host>;Port=5432;Database=<db>;Username=<user>;Password=<password>;SSL Mode=Require
```

Use the *pooled* host if Neon offers one. Never commit this string or paste it in chat.

## 2. Render (API)

1. Render dashboard → **New → Blueprint** → pick the `trustguard` repository. It reads [`render.yaml`](../render.yaml).
2. Render asks for the two values marked `sync: false`:
   - `ConnectionStrings__Default`: the Npgsql string from step 1.
   - `Security__AllowedOrigins__0`: your Vercel production URL, e.g. `https://trustguard.vercel.app`
     (you can fill this in after step 3, then redeploy).
3. After the first deploy, note the service URL (`https://trustguard-api.onrender.com`, or with a suffix if the name
   was taken). Check `https://<service>.onrender.com/api/health/ready`.

The signing key is generated by Render. The database schema is applied on startup (`Database__MigrateOnStartup`),
which is fine for one instance.

**Free plan behaviour:** the service sleeps after 15 minutes without traffic, and the next request takes about 30 to
60 seconds while it wakes. The web app keeps working in the browser meanwhile: analysis never needs the API unless
you are signed in with history on.

## 3. Vercel (web)

1. If your Render URL differs from `trustguard-api.onrender.com`, edit the `destination` of the first rewrite in
   [`vercel.json`](../vercel.json) and commit.
2. Vercel dashboard → **Add New → Project** → import the repository. Leave **Root Directory** as the repository root
   (the build also needs `shared/`). Build settings come from `vercel.json`; no environment variables are needed.
3. Deploy. Copy the production URL into Render's `Security__AllowedOrigins__0` if you have not yet.

## Things to know

- **Origin check.** The API rejects state-changing requests whose `Origin` is not its own host or in
  `Security__AllowedOrigins`. Behind the proxy the origin is the Vercel domain, so it must be listed. Preview
  deployments have different domains and will not be able to sign in; that is intentional.
- **CSP hash.** The CSP allows one inline script (the theme bootstrap) by its SHA-256 hash. CI runs
  `npm run vercel:csp` after the build and fails if the hash in `vercel.json` is stale; fix it with
  `npm run vercel:csp -- --write` in `web/`.
- **Rate limits.** Requests reach Render from Vercel's servers, so with `ForwardLimit` at its default every visitor
  looks like Vercel's address and shares one rate-limit bucket. Fine for a demo; a production service would put
  a trusted client-IP header in front or give the API its own domain behind a shared parent domain.
- **Custom domain.** If you add one, put it in `Security__AllowedOrigins__1` as well.
